# v3 修改说明：原项目缺口与本次改动

> 日期：2026-11-04　环境：Windows 11 x64，OpenJDK 21.0.13（Temurin），Maven 3.9.9
>
> 本文档汇总 v2 版本的评分缺口、v3 的全部代码/文档改动、验证结果与演示要点，供答辩与验收使用。

## 1. 原项目（v2）缺什么

对照实验要求逐项核对，v2 已完成基础分 40 分及大部分扩展（图形界面、打包解包、ZIP/GZIP 压缩、AES-GCM 加密、定时备份与数据淘汰、实时备份、元数据支持、软/硬链接），存在以下缺口：

| 编号 | 缺口 | 对应要求 | v2 现状 |
| --- | --- | --- | --- |
| GAP-1 | 自定义备份缺「用户（属主）」筛选（-3 分） | 自定义备份：路径/类型/名字/时间/尺寸/**用户** 各 3 分 | `BackupFilter` 仅 5 类条件，无法按属主筛选 |
| GAP-2 | 文件类型支持不全（约 -5 分） | 特殊文件：**管道/链接/设备**（满分 10 分） | 仅支持软/硬链接；管道、设备、socket 在扫描时跳过并提示 `Skipped unsupported special file` |
| GAP-3 | 网络备份 0 分（约 -30 分） | 网盘模式 10 分；用户管理/元数据管理/传输加密/增量备份 各 5 分 | 历史上仅 270 行匿名 HTTP 上传的演示代码，且已在提交 `a2a43b3` 中删除 |
| GAP-4 | 平台验证隐患（质量项） | 正确性、健壮性 | 64 个测试仅在 macOS 实跑；Windows 下有 5 个测试失败（硬链接识别、POSIX 权限相关）；原因：Windows JDK 公开 API 不提供文件身份（`fileKey()` 返回 null）与 `unix:mode` 类型位 |

| 文件 | 改动 |

### 2.4 网络备份全新实现（对应 GAP-3，约 1400 行）

新增包 `com.backup.network`，6 个类：

| 类 | 职责 |
| --- | --- |
| `PasswordHashes` | PBKDF2-HMAC-SHA256（210000 次迭代、256 位）口令哈希与常数时间校验 |
| `NetworkUsers` | 账号存储 `users.properties`：仅存盐值+验证值，明文口令不落盘；临时文件+原子移动写入；用户名 `[A-Za-z0-9][A-Za-z0-9._-]{0,31}` 映射为隔离目录，阻断目录穿越；支持改密（需旧口令） |
| `NetworkBackupServer` | JDK `HttpsServer` 接收服务：首次启动用 JDK `keytool` 自动生成自签名证书（SAN 含 localhost）；全部端点 Basic 认证；`/api/ping`、`/api/upload`（流式暂存 `.incoming-*.part` + 令牌）、`/api/commit`（解析清单→校验身份→原子发布归档+清单旁挂+快照索引→写最新清单→按 keepGroups 服务器端淘汰）、`/api/snapshots`、`/api/manifest`、`/api/download`、`/api/delete`（整组删除且保护最新组）；发布失败回滚本次产物；请求/响应体统一 Properties 文本 |
| `NetworkBackupClient` | HTTPS 客户端：每请求 Basic 凭据；信任库显式指定服务器密钥库文件（信任固定，不依赖 CA） |
| `NetworkBackupService` | 网络备份编排：任务号复用 `BackupService.taskIdentity`；以服务器端清单为增量基线，链规则与本地一致（一全量+至多九增量；压缩/加密/口令变化或链缺失退化为全量）；还原下载后直接复用本地 `BackupService.restoreDetailed`（链接/元数据/路径安全语义零差异） |
| `core/BackupService.java` | `taskIdentity` 由 private 改为 public static（本地与网络共用同一任务身份） |

UI（`ui/BackupFrame.java`）：新增 **Network** 标签页——服务端（存储目录、端口、启停、添加用户）+ 客户端（地址/账号、源目录、压缩/加密/增量、keep groups、备份/列表/还原/删除、连接测试），网络操作经既有 `BackupTaskGate` 与本地任务串行。

## 5. 演示要点（3 分钟）

1. **属主筛选**：Backup 页展开筛选，Owners 填当前用户名 → 只备份该属主文件；填不存在用户 → 空清单。
2. **特殊文件（macOS/Linux 演示）**：`mkfifo` 建管道 → 备份 → 清单含 `type=FIFO` 无载荷 → 还原后 `ls -l` 出现管道标志。Windows 演示时说明平台降级与警告。
3. **网络模式**：Network 页 Start server（自动生成证书）→ Add user → Test connection → 加密备份到服务器 → 改文件再备份（增量）→ List snapshots → Restore selected → keep groups=1 备 12 次只剩最新整组。

## 6. 已知边界（如实记录）

- Windows 无法在扫描期识别硬链接与特殊文件（公开 API 限制），降级为普通文件/跳过并警告；相关用例在 macOS/Linux 实跑。
- 设备重建需 root 与 `mknod`；socket 只记录不重建。
- 网络证书为自签名（SAN 含 localhost/127.0.0.1），面向本机与局域网；客户端以服务器密钥库文件固定信任。
- 网络加密链的口令一致性由客户端进程内记忆保证（与本地模型一致），换进程后自动重新全量。
