# 本地功能验收

本文提供在本地临时目录中重现行为的步骤。预期结果用于人工核对，不代表 Windows、Linux、macOS 的所有文件系统均已测试。不要选择真实资料目录进行覆盖或保留清理实验；本文不包含删除用户资料的命令。

## 1. 构建与标准测试

在仓库根目录使用 JDK 21：

```bash
java -version
mvn test
mvn clean package
```

仓库没有 Maven wrapper。当前 shell PATH 无 `mvn`，但 IntelliJ IDEA 提供了实际 Maven，可执行：

```bash
"/Applications/IntelliJ IDEA.app/Contents/plugins/maven-plugin/lib/maven3/bin/mvn" test
```

其他机器使用其已安装 Maven 的路径。无 Maven 时可编译运行应用，但这不替代 JUnit 测试：

```bash
mkdir -p target/classes
javac --release 21 -d target/classes $(find src/main/java -name '*.java' -print)
java -cp target/classes com.backup.BackupApplication
```

运行单元测试以 `mvn test` 为正式入口；实现时使用的临时辅助脚本不属于仓库交付物，不应作为验收依赖。

## 2. 建立隔离样本（macOS / Linux）

另开终端，在仓库根目录执行。所有实验文件均放在新建目录中；结束后可用文件管理器检查并自行移除该目录。

```bash
BACKUP_DEMO_DIR="$(mktemp -d "${TMPDIR:-/tmp}/backup-demo.XXXXXX")"
export BACKUP_DEMO_DIR
mkdir -p "$BACKUP_DEMO_DIR/source/docs" "$BACKUP_DEMO_DIR/source/cache" "$BACKUP_DEMO_DIR/archives" "$BACKUP_DEMO_DIR/restored"
printf 'first version\n' > "$BACKUP_DEMO_DIR/source/docs/report.txt"
printf 'notes\n' > "$BACKUP_DEMO_DIR/source/docs/notes.log"
printf 'extensionless\n' > "$BACKUP_DEMO_DIR/source/README"
printf 'hidden\n' > "$BACKUP_DEMO_DIR/source/.env"
printf 'exclude me\n' > "$BACKUP_DEMO_DIR/source/cache/temp.txt"
chmod 640 "$BACKUP_DEMO_DIR/source/docs/report.txt"
ln "$BACKUP_DEMO_DIR/source/docs/report.txt" "$BACKUP_DEMO_DIR/source/docs/report-hard.txt"
ln -s docs/report.txt "$BACKUP_DEMO_DIR/source/report-link"
printf '%s\n' "$BACKUP_DEMO_DIR"
```

`ln` 要求文件系统支持链接且目录可写。Windows 应使用有权限的终端与支持链接的文件系统另行验收；创建符号链接可能需要开发者模式或额外权限。不要为了通过演示而修改系统权限或以管理员身份覆盖真实文件。

## 3. GUI 筛选与格式演示

在 Backup 页设置源为样本 `source`、目标为 `archives`。填写名称 `selection`，路径包含 `docs/**;README;.env`，路径排除 `cache/**`，扩展名 `txt`，勾选无扩展名，名称 `report*;README;.env`；其余时间/大小条件留空，保留组数为 0。

预期归档包含 `report.txt`、`report-hard.txt`、`README`、`.env` 及必要父目录，不含 `notes.log`、缓存文件或未被包含规则选中的链接。清空扩展名并保留无扩展名勾选后，只选无扩展名文件；取消勾选后不再限制类型。路径和名称规则区分大小写，扩展名不区分大小写。

分别填写大小上下界为同一已知文件的字节数，核对端点被包含；修改时间输入使用本地时区 `yyyy-MM-dd HH:mm:ss`（例如 `2026-11-02 09:30:00`），核心 API 则使用 epoch 毫秒；上下界包含端点。输入最小值大于最大值应报错。清空筛选后分别测试 ZIP、GZIP、加密 ZIP 和加密 GZIP。每份归档旁应有 `.manifest.properties` 和 `.snapshot.properties`；加密归档用正确口令可还原，错误口令应失败。旧 v1 样本如有，应单独保存并逐种还原验证；本步骤不生成旧格式样本，不能据此声明兼容性已经人工验证。

## 4. 可重复的十一份备份与保留实验

使用同一个 `BackupService` 才能观察连续增量。下列 Java 源文件由标准 JDK 21 运行，不依赖临时测试框架。先完成第 1 节直接编译，在同一终端执行：

```bash
cat > "$BACKUP_DEMO_DIR/Demo.java" <<'JAVA'
import com.backup.core.*;
import java.nio.file.*;
import java.util.*;

class Demo {
    public static void main(String[] args) throws Exception {
        Path root = Path.of(System.getenv("BACKUP_DEMO_DIR"));
        Path source = root.resolve("source"), destination = root.resolve("retention");
        BackupService service = new BackupService();
        BackupOptions options = new BackupOptions(source, destination, "retention",
                CompressionType.ZIP, true, false, new char[0], BackupFilter.all(), 1);
        for (int i = 1; i <= 11; i++) {
            Files.writeString(source.resolve("round.txt"), "round " + i);
            BackupResult result = service.backup(options);
            Path index = destination.resolve(result.archivePath().getFileName() + ".snapshot.properties");
            Properties p = new Properties();
            try (var reader = Files.newBufferedReader(index)) { p.load(reader); }
            System.out.printf("round=%d sequence=%s group=%s archive=%s%n", i,
                    p.getProperty("sequence"), p.getProperty("groupId"), result.archivePath().getFileName());
        }
        try (var files = Files.list(destination)) {
            System.out.println("retained index count=" + files.filter(p -> p.toString().endsWith(".snapshot.properties")).count());
        }
    }
}
JAVA
java --class-path target/classes "$BACKUP_DEMO_DIR/Demo.java"
```

预期前十轮同组、序号 1..10，第十一轮为新组序号 1；`keepGroups=1` 后旧组十份归档及两类旁挂文件被一起清理，索引数量为 1。仅在新建样本目录中运行一次；若再次执行，每次新进程首轮均全量，控制台可观察历史组被保留策略处理。

把演示目标改为另一个全新子目录，并把 `keepGroups` 改为 0，再运行：仍应第十一轮全量，十一份索引均保留。将源、名称或筛选改为另一任务后，不应删除原任务归档。在 GUI 中重启程序，再备份同一任务，第一份应全量。切换压缩、加密、有效口令或保留启用状态也应全量。

对新的独立演示目录，可手工移走旧组的一个清单，再触发保留；该不完整组应保留并出现警告。可放置无关 `.zip` 文件或损坏 `.snapshot.properties` 文件确认不会被猜测删除。损坏索引会使本轮保守跳过清理，实际保留数量可能超过设定值。

## 5. 还原与链接/权限核对

使用未筛选的样本全量归档，还原至 `restored`。然后修改 `source/docs/report.txt` 并在同一服务中创建增量，手动按全量、增量顺序还原至同一目录。删除源中的 `notes.log` 后备份并叠加还原，目标中的旧 `notes.log` 仍应存在：增量还原不做删除同步，也不自动寻找完整链。

Unix 检查链接：

```bash
readlink "$BACKUP_DEMO_DIR/restored/report-link"
ls -li "$BACKUP_DEMO_DIR/restored/docs/report.txt" "$BACKUP_DEMO_DIR/restored/docs/report-hard.txt"
```

预期符号链接目标为 `docs/report.txt`；支持硬链接的文件系统上，两份已恢复硬链接文件应具有相同 inode。权限/属主/属组可用 `ls -l` 检查；修改、访问、创建时间需使用本平台工具分别检查。读取文件本身可能改变访问时间，创建时间也未必允许设置。普通用户通常无法切换到任意属主/属组；不支持的操作应产生警告，不能据此要求完全相同。特别地，符号链接的权限、属主、属组恢复在所有平台主动跳过并警告：macOS 的权限 API 即使指定不跟随仍可能修改外部链接目标。链接时间仍通过不跟随方式尽力设置。

另建新还原目标测试硬链接防护，先准备目录外的样本文件与目标硬链接：

```bash
mkdir -p "$BACKUP_DEMO_DIR/hardlink-restore/docs"
printf 'outside sentinel\n' > "$BACKUP_DEMO_DIR/outside.txt"
ln "$BACKUP_DEMO_DIR/outside.txt" "$BACKUP_DEMO_DIR/hardlink-restore/docs/report.txt"
```

向 `hardlink-restore` 还原包含 `docs/report.txt` 的全量归档后，目标应成为归档内容，而 `outside.txt` 仍为 `outside sentinel`，表明替换目标没有截断外部硬链接。再建立另一个新目标，让 `docs` 成为指向还原目录外侧的符号链接：

```bash
mkdir -p "$BACKUP_DEMO_DIR/symlink-restore" "$BACKUP_DEMO_DIR/outside-dir"
printf 'do not overwrite\n' > "$BACKUP_DEMO_DIR/outside-dir/report.txt"
ln -s "$BACKUP_DEMO_DIR/outside-dir" "$BACKUP_DEMO_DIR/symlink-restore/docs"
```

向 `symlink-restore` 还原应拒绝该目标路径，`outside-dir/report.txt` 必须保持原内容。

## 6. v3 功能验收（属主筛选 / 特殊文件 / 网络模式）

**属主筛选**：在 Backup 页展开文件筛选，Owners 填当前用户名（`ls -l` 或系统属性查看），仅保留该属主文件；填 `no-such-user` 后备份应产出仅含目录结构的清单（或空清单）并给出说明。属主与扩展名组合应同时命中两条规则。

**特殊文件（POSIX）**：

```bash
mkfifo "$BACKUP_DEMO_DIR/source/pipe"
```

备份后检查清单（`*.manifest.properties`）应含 `type=FIFO` 且无数据载荷；还原到空目录后 `ls -l` 应显示 `prw-rw----` 一类管道标志。无 `mkfifo`/`mknod` 权限的平台还原应产生警告而整体还原成功。设备文件条目在清单中带 `主:次` 设备号；套接字只记录、不重建并警告。Windows 不做以上检查，记录为平台降级。

**网络模式**：

1. Network 页选择空存储目录，Start server；确认日志出现端口与 TLS，存储目录出现 `server-keystore.p12`。
2. 填用户名/密码 Add user；客户端填 localhost、端口、账号后 Test connection 应成功；改错密码应 401 失败。
3. 选源目录 Back up to server → List snapshots 出现 `full` 归档；修改一个文件再次备份 → 列表出现 `incremental`。
4. Restore selected 至空目录（全量），再按顺序还原增量；核对内容。
5. keep groups 填 1 连续备份 12 次，服务器目录应只剩最新整组的归档+清单+索引；Delete selected group 对最新组应拒绝删除。
6. 记录：服务器清单（`*.manifest.properties`）中 `encrypted=true` 时下载归档为 `.enc`，错误口令还原失败且不产生内容。

## 7. 记录结果

每次记录 JDK 版本、操作系统、文件系统、普通用户权限、压缩/加密选项、预期与实际、日志警告。分别记录编译、JUnit、GUI 手工演示和平台能力检查；未执行的项目记为未执行，不将单平台结果写成全平台通过。v3 起产品包含本地与网络两种模式；网络验收记录需同时注明服务器与客户端所在主机、端口与账号名（不含口令）。
